THE BUSINESS QUESTION

What does the underlying retail data actually reveal?

Before building executive dashboards, the dataset needed to be interrogated at the source.

The SQL analysis was designed to answer questions around sales performance, revenue movement, customer behaviour, payment patterns, product performance, branch execution and inventory risk. This created a validated analytical foundation for the subsequent Power BI reporting layer.

Eight checks before a single chart.

Every number on the Power BI dashboard depends on these. Each check below is a query run against the loaded data, with the result it returned.

8 / 8 checks passed
  1. Every staging row loaded Transactions_Staging 1,807,529 vs FactSales 1,807,529
    0 difference
  2. No orphan products Orphan_Product_References
    0 rows
  3. No invalid customers Invalid_Customer_References
    0 rows
  4. No invalid employees Invalid_Employee_References
    0 rows
  5. No duplicate receipt lines GROUP BY Receipt_No, Line_Number HAVING COUNT(*) > 1
    0 rows
  6. No missing keys NULL Receipt_No, Product_ID, Employee_ID, Branch_Code, Transaction_Date, Line_Total
    0 nulls
  7. Every product sold has stock records FactSales LEFT JOIN FactInventory WHERE I.Product_ID IS NULL
    0 rows
  8. Line totals add up ABS(Line_Total − (Quantity × Unit_Price − Discount_Amount + VAT)) > 0.01
    3,078 flaggedExplained

    3,078 of 1,807,529 lines were off, and none by more than ₦0.05. Unit_Price is stored as a float, and every gap is an exact binary fraction such as 1/32 of a naira: storage precision, not pricing logic.
